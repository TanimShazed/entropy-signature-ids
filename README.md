# Entropy-Signature Anomaly Scoring for Lightweight Network Intrusion Detection

> A training-free alternative to trained anomaly detectors for intrusion detection, evaluated
> honestly against the baselines it does and does not beat.

This repository contains the paper, the full experiment notebook, and every figure, table, and log
generated by that notebook, for a study on closed-form, gradient-free intrusion detection built from
per-flow entropy signatures and Mahalanobis distance.

**Status:** Submitted for double-blind peer review. This repository is anonymized — no author names,
institutional affiliations, or identifying paths appear anywhere in it. Author information will be
added after the review process concludes.

## What this is

Deep learning intrusion detectors post the strongest published accuracy, but they are also the most
expensive to (re)train — a real cost on resource-constrained gateways where traffic drifts and models
need periodic refitting. This project asks a direct question: how far can a **training-free** detector
get, using nothing but closed-form statistics computed from a handful of per-flow entropy features, and
where exactly does it fall short of the standard lightweight baselines?

The method:
1. Partitions each network flow's features into semantic roles (rate, count, byte, and — for one
   dataset — a connection-state role).
2. Reduces each role to a single scalar via Shannon entropy or dispersion.
3. Fits a Gaussian to that low-dimensional signature using **only normal-labeled training flows**, in
   closed form — one pass over the data, no gradient descent anywhere.
4. Scores new flows by Mahalanobis distance against a validation-selected threshold.

No neural network, no iterative solver, no hyperparameter search loop. Fitting is a single closed-form
computation; the entire benefit case rests on that.

## What we found — the honest version

We report wins and losses with equal weight, because a lightweight-detection paper that hides its weak
points is not useful to a practitioner deciding whether to use this method.

| | NSL-KDD | Synthetic IoT benchmark |
|---|---|---|
| **Proposed vs. Isolation Forest (F1)** | 0.825 vs. **0.877** (loses) | **0.749** vs. 0.741 (wins) |
| **Proposed vs. One-Class SVM (F1)** | 0.825 vs. **0.863** (loses) | **0.749** vs. 0.740 (wins) |
| **Proposed vs. MLP (F1 / fit time)** | **0.825** vs. 0.764 / **0.24 s** vs. 6.08 s (wins both) | — |

- On NSL-KDD, a data-driven fourth signature dimension (mined from previously unused categorical
  fields) raises F1 from 0.787 → 0.825 and closes ~40–49% of the gap to Isolation Forest / One-Class
  SVM — **without closing it**. We report the remaining gap plainly rather than only the improvement.
- The ablation behind that number surfaces something the headline hides: dropping the
  count-dispersion signature component entirely *improves* both F1 and AUC over the "full" signature,
  and a single byte-entropy feature alone beats the three-feature baseline it was meant to justify. One
  original component was actively harmful, not merely redundant.
- On a second, synthetic IoT-flow benchmark (built because we could not obtain reliable,
  authentication-free access to a real second intrusion dataset — see [Limitations](#honest-limitations)),
  the same method **outperforms** Isolation Forest and One-Class SVM on F1. Decomposing precision and
  recall shows why: both baselines chase recall above 0.99 at the cost of precision near 0.59 on that
  benchmark, while the proposed method holds a more balanced 0.80 / 0.71.
- Two targeted interventions for the method's weakest point — recall on rare R2L and U2R attacks — are
  reported **including where they fail**. A closed-form ensemble narrows the Isolation Forest gap
  slightly further (F1 0.825 → 0.839, p ≈ 0.02) but does not repair rare-class recall, which remains an
  open problem.

Every number above is reproduced exactly in [`results/`](results/) and traced to the notebook cell that
produced it. Nothing in this README or the paper is asserted without a corresponding table or figure in
this repository.

## Reproducing the results

The notebook is self-contained: it installs its own dependencies, downloads NSL-KDD directly (no
authentication required), generates the synthetic IoT benchmark in-notebook, and writes every figure
and table in this repository's `results/` folder. Nothing is hand-edited after the fact.

```bash
# Option A — Google Colab (recommended, no local setup)
# Upload notebook/entropy_signature_ids.ipynb to https://colab.research.google.com and Run All.

# Option B — local environment
pip install -r requirements.txt
jupyter nbconvert --to notebook --execute notebook/entropy_signature_ids.ipynb
```

Every run uses fixed seeds (42–46) and completes in well under two minutes on CPU alone — the entire
method, baselines included, is deliberately lightweight; no GPU is required despite the notebook's
Colab GPU runtime setting (kept only for parity with the MLP baseline's typical deployment target).

## Method and baselines

| Method | Type | Training |
|---|---|---|
| **Entropy Signature (proposed)** | Closed-form anomaly scorer | None — closed-form fit on normal data only |
| Isolation Forest | Unsupervised ensemble | Iterative, but no labels required |
| One-Class SVM | Unsupervised kernel method | Iterative, but no labels required |
| Logistic Regression | Supervised linear baseline | Iterative, requires labels |
| MLP (64, 32) | Supervised deep baseline | Iterative (gradient descent), requires labels |

Datasets: [NSL-KDD](https://www.unb.ca/cic/datasets/nsl.html) (real, standard benchmark) and a
literature-grounded synthetic IoT-flow benchmark generated in-notebook with a tunable attack-strength
parameter for controlled sensitivity analysis (see [Limitations](#honest-limitations)).

## Honest limitations

Stated in full in the paper's Discussion section, and repeated here so they are not missed:

1. Isolation Forest and One-Class SVM outperform the proposed method on NSL-KDD's standard task even
   after refinement. The defensible claim is cost advantage, not superiority, on that benchmark.
2. The second dataset is synthetic. We could not obtain reliable, authentication-free access to a real
   second intrusion dataset (UNSW-NB15, CICIoT2023, TON_IoT) in our evaluation environment, and say so
   rather than silently substituting one. It supports genuine sensitivity analysis a fixed dataset
   cannot, but is not a substitute for real IoT traffic validation.
3. The NSL-KDD signature refinement did not transfer to the synthetic IoT schema — mining unused
   categorical fields is worth trying per-deployment, not assumed as a guaranteed gain.
4. The count-dispersion signature component is actively harmful on NSL-KDD yet clearly useful on the
   IoT benchmark. We have no data-independent rule for which components to keep in advance.
5. Rare-class recall (R2L, U2R) remains weak across every method tested, our own included, and neither
   targeted intervention we tried resolved it. We treat this as a genuinely open problem.
